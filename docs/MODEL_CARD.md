# Model card

## Intended use
Clinical-trial supply teams balance enrollment uncertainty, replenishment lead time and kit expiry. Spreadsheet-only planning makes stockout warnings and reorder assumptions hard to audit.

The model target is **weekly_kit_demand**, in **kits per week**. Intended users are portfolio reviewers and developers testing the workflow. It has no demonstrated real-world validity.

## Training data
Poisson enrollment times kits per participant, plus small Gaussian noise, generates weekly demand. Only enrollment and kits enter the ML model; inventory policy is calculated separately.

800 seeded records are generated by `app.domain.simulate`, called by `python -m scripts.generate_data`. Data provenance is synthetic and uses no external or employer data. Inputs to the model: enrollment_per_week, kits_per_participant. Operational fields not listed here are used only in explicit policy calculations.

## Training and evaluation
Seed 42 produces a fixed 75/25 split. Classification stratifies by label; preprocessing is fit on training data only. Regression compares a random forest to a mean computed only on training data. No tuning uses the test set. The served estimator remains trained on the same 600 training records so published test metrics correspond to the actual model. Training happens once per process, with no unsafe pickle deserialization.

The 90th-percentile absolute test residual is descriptive, not a calibrated uncertainty interval. Changing a generator, feature schema or dependency version requires rerunning evaluation. No prospective, external-site or temporal validation has occurred.

## Limitations and next experiments
Synthetic labels encode simplified relationships and do not establish clinical or financial validity. Test the local baseline against an authorized real dataset, select metrics reflecting asymmetric operational costs, perform temporal/site splits where applicable, check subgroup and out-of-distribution errors, calibrate probabilities if needed, and implement drift monitoring. RAG is lexical; paraphrase recall is limited. Check `reports/evaluation.json` for actual generated metrics rather than assumed benchmarks.
